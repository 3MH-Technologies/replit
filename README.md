# 🐳 HostBot — لوحة بسيطة لرفع وتشغيل ملفات Python

لوحة واحدة، بلا تعقيد:

```
دخول الأدمن  →  ارفع ملفات البوت (.py)  →  اضغط ▶ تشغيل  →  تابع الكونسول
```

---

## التشغيل محليًا

```bash
pip install -r requirements.txt
python app.py
# افتح: http://127.0.0.1:7860
```

بيانات الدخول الافتراضية: `admin` / `admin` — **غيّرها فورًا** عبر متغيرات البيئة.

## متغيرات البيئة

| المتغير | الافتراضي | الوصف |
|---|---|---|
| `ADMIN_USER` | `admin` | اسم مستخدم الأدمن |
| `ADMIN_PASS` | `admin` | كلمة المرور — **عيّنها قبل النشر** |
| `PORT` | `7860` | منفذ الخدمة |
| `SESSION_COOKIE_SECURE` | `false` | اجعلها `true` إذا كنت على HTTPS دائمًا |
| `SECRET_KEY` | يُشتق تلقائيًا | مفتاح جلسات اختياري |
| `BOT_NICE` | `10` | أولوية البوتات (أقل من اللوحة حتى تبقى سريعة) |
| `MONITOR_INTERVAL` | `15` | كل كم ثانية يفحص مراقب التشغيل البوتات |
| `MAX_FAILS` | `5` | أقصى محاولات إعادة تشغيل تلقائية متتالية |
| `KEEPALIVE_URL` | فارغ | رابط اللوحة العام لنبضة حياة دورية (مثل رابط Space) |
| `KEEPALIVE_INTERVAL` | `240` | كل كم ثانية تُرسل نبضة الحياة |
| `MAX_BOT_MEM_MB` | `0` | حد ذاكرة لكل بوت بالميغابايت (0 = بلا حد) |
| `SHOW_LIB_LOGS` | `0` | اجعلها `1` لإظهار ثرثرة المكتبات في الكونسول (httpx/telegram…) |
| `RESTART_ON_CLEAN_EXIT` | `0` | اجعلها `1` لإعادة تشغيل البوت حتى لو انتهى برمز خروج 0 |

## كيف يعمل

- كل بوت = مجلد داخل `BOTS/` فيه ملفاته و `server.log` و `meta.json`.
- زر **⬆️ رفع py** في الأعلى: ترفع الملفات فيُنشأ بوت تلقائيًا باسم أول ملف.
- داخل أي بوت: 📂 الملفات (رفع / تحرير داخل المتصفح / حذف / تعيين الملف الرئيسي ★)
  و 📜 الكونسول (سجل حي + زر **نسخ السجل** + تفريغ).
- **الكونسول يعرض مخرجات ملف البوت فقط**: ثرثرة المكتبات (httpx / telegram /
  aiohttp / proxyscrape …) مخفية تلقائيًا. أعِدها بـ `SHOW_LIB_LOGS=1`.
- **التشغيل التلقائي للمكتبات الناقصة**: إذا احتاج البوت مكتبة غير مثبتة،
  `runner.py` يثبّتها من pip ويعيد التشغيل وحده. ومثلها `requirements.txt`
  يُثبّت تلقائيًا أول مرة (وأي مرة يتغيّر فيها).
- **التشغيل التلقائي للبوتات**: أي بوت كنت قد شغّلته يعود تلقائيًا إذا أُعيد
  تشغيل اللوحة (إيقافه يدويًا يلغي ذلك).

## 🛡️ الاستمرارية وتوزيع الضغط

نظام متكامل — لا يتوقف السيرفر، ويتوزّع الحمل بدل الانهيار:

- **مراقب تشغيل دائم**: أي بوت مطلوب تشغيله وتوقف (انهيار أو خروج) يُعاد تشغيله
  تلقائيًا خلال ثوانٍ.
- **تمييز الانتهاء الطبيعي**: لو انتهى الملف فورًا برمز خروج 0 (بدون حلقة تشغيل)
  لا تدور اللوحة في حلقة إعادة تشغيل بلا معنى — تُبلّغك بالسبب في الكونسول وتوقف
  المحاولات. البوت الذي عمل فترة ثم انتهى طبيعيًا يُعاد تشغيله تلقائيًا
  (أو اجعل `RESTART_ON_CLEAN_EXIT=1` لإعادة التشغيل دائمًا).
- **حماية من حلقات الأعطال**: بعد `MAX_FAILS` محاولات فاشلة متتالية خلال 10 دقائق
  يتوقف الإعادة التلقائية ويُكتب السبب في الكونسول — لا تدوير لا نهائي يأكل المعالج.
- **تصفير العدّاد**: إذا بقي البوت مستقرًا دقيقتين يرجع العدّاد صفرًا.
- **توزيع حمل الإقلاع**: البوتات تُشغّل بالتتابع (لا كلها دفعة واحدة) بعد إعادة
  تشغيل اللوحة.
- **بدون تكرار**: إذا أُعيد تشغيل اللوحة وحدها بينما بوت ما زال يعمل، تتبنّاه
  اللوحة كما هو (ملف `.pid`) بدل تشغيل نسخة ثانية منه.
- **أولوية منخفضة (nice)**: البوتات تعمل بأولوية أقل من اللوحة، فتبقى الواجهة
  مستجيبة تحت الضغط.
- **حد ذاكرة اختياري**: `MAX_BOT_MEM_MB` يمنع بوتًا واحدًا من أكل ذاكرة الجميع
  (البوت المتجاوز يفشل وحده ثم يُعاد تشغيله وفق حماية الأعطال، واللوحة تبقى تعمل).
- **خادم ويب متعدد الخيوط** (`16` خيطًا): يخدم عدة طلبات في نفس الوقت، و`HEALTHCHECK`
  يجعل المنصّة تعيد تشغيل الخدمة تلقائيًا إن توقفت.
- **نبضة حياة**: كل 4 دقائق يرسل اللوحة طلبًا لنفسه على `/health`، ويمكنك إضافة
  `KEEPALIVE_URL` (رابط السبيس العام) أو ربط UptimeRobot على `/health` لمنع النوم.

## النشر

### Hugging Face Spaces (نفس المكان القديم)

الملف `README.md` هذا يحمل ترويسة Space الجاهزة (`sdk: docker`, المنفذ 7860)،
فقط ارفع محتوى المجلد إلى السبيس:

```bash
git remote add hf https://huggingface.co/spaces/<اسمك>/<اسم-السبيس>
git push -f hf main
```

> نصيحة: استخدم خدمة مثل UptimeRobot على `https://<سبيسك>/health` ليبقى
> السبيس مستيقظًا قدر الإمكان.

### GitHub

المستودع على حسابك المسجّل: `3MH-Technologies/replit` (**عام/Public**) والريموت
`origin` مضبوط عليه بالفعل:

```bash
git push origin main
```

## ⚠️ تنبيه أمني مهم

الكود القديم (النسخة السابقة من هذا المستودع) كان يحتوي **توكن GitHub مكتوبًا
داخل `app.py`** (متغير `DATAREPO_TOKEN`) وكلمة مرور افتراضية للأدمن. إذا كان
المستودع عامًا فهذا التوكن مكشوف:

1. أبطِله فورًا: GitHub → Settings → Developer settings → Personal access tokens.
2. عيّن `ADMIN_PASS` قوية جديدة في بيئة التشغيل.
