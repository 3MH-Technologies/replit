# 🐳 HostBot

لوحة عربية احترافية لرفع وتشغيل بوتات **Python** وإدارتها من المتصفح.

```
تسجيل دخول الأدمن  →  رفع ملفات .py أو أرشيف .zip  →  تشغيل  →  متابعة السجل
```

---

## ✨ المميزات

- **رفع Python و ZIP**: ارفع ملفات `.py` مباشرة، أو أرشيف `.zip` كاملًا
  (مشروع، مجلدات، `requirements.txt`، ملفات `.env`) وسيُفك تلقائيًا.
- **اكتشاف ذكي للملف الرئيسي**: يختار `main.py` / `bot.py` / `app.py` تلقائيًا،
  ويمكنك تغييره بضغطة ★.
- **مدير ملفات كامل**: إنشاء مجلدات وملفات جديدة (بما فيها `.env`)، تحرير
  الملفات داخل المتصفح، رفع، تنزيل، حذف، واستخراج أرشيفات ZIP.
- **كونسول حي**: سجل التشغيل مع تحديث تلقائي، نسخ، تنزيل، وتفريغ.
- **تشغيل تلقائي للمكتبات**: تثبيت `requirements.txt` وأي مكتبة ناقصة عند
  التشغيل، ثم إعادة تشغيل البوت تلقائيًا.
- **دعم `.env`**: يُحمَّل ملف `.env` من مجلد البوت تلقائيًا عند التشغيل (دون
  تجاوز متغيرات البيئة الموجودة).
- **استمرارية قوية**: مراقب دائم يعيد تشغيل البوتات المتوقفة بمهل متصاعدة،
  مع تبنّي العمليات الناجية بعد إعادة تشغيل اللوحة.
- **إدارة موارد**: عرض CPU / RAM / مدة التشغيل لكل بوت، وأولوية أقل للبوتات
  حتى تبقى اللوحة مستجيبة.
- **واجهة عصرية**: تصميم داكن متجاوب، سحب وإفلات للملفات، بحث، إشعارات،
  ونوافذ تأكيد مدمجة.
- **أمان**: جلسات محمية، مقارنة كلمات مرور ثابتة الزمن، حد لمحاولات الدخول،
  حماية من path traversal وzip-slip، وترويسات أمان HTTP.

## 🚀 التشغيل محليًا

```bash
python -m venv .venv
# Windows
.venv\Scripts\activate
# Linux / macOS
source .venv/bin/activate

pip install -r requirements.txt
python app.py
```

افتح: <http://127.0.0.1:7860>

بيانات الدخول الافتراضية: `admin` / `admin` — **عيّن كلمة مرور قوية قبل النشر**.

---

## ⚙️ متغيرات البيئة

| المتغير | الافتراضي | الوصف |
|---|---|---|
| `ADMIN_USER` | `admin` | اسم مستخدم الأدمن |
| `ADMIN_PASS` | `admin` | كلمة المرور — **عيّنها قبل النشر** |
| `PORT` | `7860` | منفذ الخدمة |
| `SECRET_KEY` | يُشتق تلقائيًا | مفتاح جلسات ثابت (مستحسن في الإنتاج) |
| `SESSION_COOKIE_SECURE` | `false` | اجعلها `true` عند العمل على HTTPS دائمًا |
| `TRUST_PROXY` | `false` | اجعلها `true` خلف reverse proxy موثوق لقراءة IP العميل |
| `MAX_UPLOAD_MB` | `200` | أقصى حجم للطلب الواحد |
| `MAX_EXTRACT_MB` | `500` | أقصى حجم بعد فك ضغط ZIP |
| `MAX_ZIP_ENTRIES` | `3000` | أقصى عدد عناصر داخل الأرشيف |
| `BOT_NICE` | `10` | أولوية البوتات (أقل من اللوحة) |
| `MONITOR_INTERVAL` | `15` | كل كم ثانية يفحص المراقب البوتات |
| `RESTART_DELAY_BASE` | `3` | أول مهلة انتظار قبل إعادة تشغيل بوت خرج سريعًا |
| `RESTART_DELAY_MAX` | `60` | أقصى مهلة بين محاولات إعادة التشغيل |
| `KEEPALIVE_URL` | فارغ | رابط عام اختياري لنبضة حياة دورية |
| `KEEPALIVE_INTERVAL` | `240` | كل كم ثانية تُرسل نبضة الحياة |
| `MAX_BOT_MEM_MB` | `0` | حد ذاكرة لكل بوت بالميغابايت (0 = بلا حد) |
| `SHOW_LIB_LOGS` | `0` | اجعلها `1` لإظهار سجلات المكتبات في الكونسول |

انسخ `.env.example` إلى `.env` إن أردت تشغيلًا محليًا منظمًا.

## 📦 رفع ZIP و Python

- زر **⬆️ رفع ملفات** يقبل `.py` و `.zip` معًا.
- عند رفع ZIP:
  - تُستخرج الملفات والمجلدات مع الحفاظ على هيكلها.
  - إذا كان الأرشيف كله داخل مجلد واحد (مثل تحميل مشروع من GitHub) يُرفع
    محتواه تلقائيًا إلى جذر البوت.
  - تُتجاهل ملفات النظام المؤقتة مثل `__MACOSX` و`.DS_Store`.
  - يُمنع أي مسار يخرج عن مجلد البوت (zip-slip)، وتُتجاهل الروابط الرمزية
    والأرشيفات المشفّرة.
  - يُختار الملف الرئيسي تلقائيًا إن لم يكن محددًا.
- يمكنك أيضًا رفع ZIP داخل مجلد معيّن من مدير الملفات، أو استخراج أرشيف
  موجود بزر **📦 استخراج**.

### ملفات `.env`

- أنشئ ملفًا جديدًا باسم `.env` من مدير الملفات، أو ارفعه مع المشروع.
- ملفات `.env` داخل مجلدات البوتات مدعومة بالكامل (إنشاء، تحرير، رفع، تنزيل).
- لا تُرفع ملفات البوتات إلى Git لأن مجلد `BOTS/` مستبعد في `.gitignore`.

```

├── server.log          # سجل التشغيل
├── .env                # اختياري
└── ...                 # ملفات المشروع
```

## 🛡️ الاستمرارية وتوزيع الضغط

- **مراقب تشغيل دائم**: أي بوت مطلوب تشغيله وتوقف يُعاد تشغيله تلقائيًا.
- **مهل متصاعدة**: البوت الذي يخرج فورًا يُعاد تشغيله بعد 3 → 6 → 12 → 24 →
  48 → 60 ثانية حتى لا يستهلك المعالج بلا فائدة.
- **استمرارية بعد الخروج الطبيعي**: البوت الذي عمل فترة كاملة ثم انتهى يُعاد
  تشغيله فورًا.
- **إيقاف نهائي يدوي فقط**: زر **⏹ إيقاف** هو الذي يوقف الإعادة التلقائية.
- **تصفير العدّاد**: إذا بقي البوت مستقرًا دقيقتين يعود عدّاد الأعطال صفرًا.
- **بدون تكرار**: إذا أُعيد تشغيل اللوحة وحدها، تتبنّى البوتات التي ما زالت
  تعمل عبر ملف `.pid` بدل تشغيل نسخة ثانية.
- **نبضة حياة**: طلب دوري على `/health`، مع إمكانية إضافة `KEEPALIVE_URL`.

## 🐳 النشر باستخدام Docker

```bash
docker build -t hostbot .
docker run -d --name hostbot \
  -p 7860:7860 \
  -e ADMIN_USER=admin \
  -e ADMIN_PASS='كلمة-مرور-قوية' \
  -e SECRET_KEY='مفتاح-عشوائي-طويل' \
  -v hostbot-data:/app/BOTS \
  --restart unless-stopped \
  hostbot
```

أو باستخدام Docker Compose:

```bash
cp .env.example .env
# عدّل .env ثم:
docker compose up -d --build
```

> **مهم:** استخدم Volume لمجلد `BOTS/` حتى لا تفقد بوتاتك عند إعادة بناء
> الحاوية.

### خادم VPS بدون Docker

```bash
pip install -r requirements.txt
ADMIN_USER=admin ADMIN_PASS='كلمة-مرور-قوية' \
  gunicorn -b 0.0.0.0:7860 -w 1 --threads 16 --timeout 600 app:app
```

يفضّل وضع الخدمة خلف Nginx أو Caddy مع HTTPS، وضبط
`SESSION_COOKIE_SECURE=true`.

## 🔐 ملاحظات أمنية

1. **غيّر `ADMIN_PASS` فورًا** قبل النشر، واستخدم كلمة مرور طويلة.
2. عيّن `SECRET_KEY` ثابتًا في الإنتاج حتى لا تنتهي الجلسات عند كل إعادة تشغيل.
3. شغّل اللوحة على HTTPS دائمًا عند تعريضها للإنترنت.
4. لا تضع أسرارًا داخل ملفات المشروع المرفوعة إلى مستودع عام.
5. راجع صلاحيات المستخدم الذي يشغّل الخدمة، وامنع الوصول المباشر إلى مجلد
   `BOTS/` من خارج التطبيق.
